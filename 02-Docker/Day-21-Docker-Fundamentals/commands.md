# Day 21: Docker Commands & Meaning

## 1. Basic Docker commands

### Check Docker installation
```bash
docker --version
```
Shows the installed Docker version.

### List running containers
```bash
docker ps
```
Displays containers currently running.

### List all containers
```bash
docker ps -a
```
Shows both running and stopped containers.

### List local images
```bash
docker images
```
Displays all images stored locally on the machine.

### Pull an image from Docker Hub
```bash
docker pull nginx
```
Downloads the `nginx` image from Docker Hub.

### Run a container
```bash
docker run nginx
```
Creates and starts a container from the `nginx` image.

### Run a container in detached mode
```bash
docker run -d nginx
```
Runs the container in the background.

### Run a container with port mapping
```bash
docker run -p 3000:3000 node-api
```
Maps host port `3000` to container port `3000`.

### Stop a running container
```bash
docker stop <container_name_or_id>
```
Stops a running container gracefully.

### Remove a container
```bash
docker rm <container_name_or_id>
```
Deletes a stopped or running container.

### Remove an image
```bash
docker rmi <image_name>
```
Deletes an image from the local system.

## 2. Build commands

### Build an image from a Dockerfile
```bash
docker build -t mern-api:1.0 .
```
Builds a Docker image named `mern-api` with tag `1.0` using the Dockerfile in the current directory.

### Build with a specific Dockerfile path
```bash
docker build -f Dockerfile.prod -t app:prod .
```
Builds using a different Dockerfile name.

---

## 3. Log and debug commands

### Show container logs
```bash
docker logs mern-api
```
Displays logs generated by the container.

### Follow logs live
```bash
docker logs -f mern-api
```
Shows new log lines in real time.

### Inspect container metadata
```bash
docker inspect mern-api
```
Shows detailed JSON metadata about the container configuration and runtime state.

### Open a shell inside a running container
```bash
docker exec -it mern-api sh
```
Executes an interactive shell inside the container.

### Print a container's mapped port
```bash
docker port mern-api
```
Shows what host port is mapped to which container port.

---

## 4. Dockerfile instructions

### Base image
```dockerfile
FROM node:22-alpine
```
Selects the base image used to build the container.

### Working directory
```dockerfile
WORKDIR /app
```
Sets the container working directory.

### Copy files
```dockerfile
COPY package*.json ./
COPY . .
```
Copies files from the host machine into the container image.

### Install dependencies
```dockerfile
RUN npm ci
```
Runs a command during the image build process.

### Runtime command
```dockerfile
CMD ["node", "server.js"]
```
Defines the startup command when the container runs.

### Expose port
```dockerfile
EXPOSE 3000
```
Documents which port the container expects to use.

## 5. Docker networking concepts

### Basic port mapping
```bash
docker run -p 8080:3000 app
```
Host port `8080` is forwarded to container port `3000`.

### Example
```text
localhost:8080
    |
    v
container:3000
```

This means the application inside the container is still listening on `3000`, but users reach it from the host on `8080`.

## 7. Common interview explanation phrases

- `docker run` creates a running instance of an image.
- `docker build` creates an image from a Dockerfile.
- `EXPOSE` does not publish the port by itself.
- `-p` publishes the port from the container to the host.
- `CMD` defines the default runtime command.
- `RUN` runs at build time.
- Docker isolates application execution while sharing the host kernel.

---

## 8. Practical notes

- Use `docker logs` before restarting a container when debugging.
- Use `docker exec` to inspect the file system and process state from inside the container.
- Use port mapping to expose app ports to the host or outside network.
- Use `0.0.0.0` when binding a service inside a container so it accepts traffic from outside the local loopback interface.

---

## 9. Example full workflow

```bash
docker build -t mern-api:1.0 .
docker run -d --name mern-api -p 3000:3000 mern-api:1.0
docker ps
docker logs mern-api
curl http://localhost:3000/health
docker exec -it mern-api sh
```

This is the basic Docker production debugging workflow for a Node.js service.
